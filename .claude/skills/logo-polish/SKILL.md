# Logo polish

The wordmark (`components/logo.tsx`) is a deliberate two-typeface signature
— "Se" in Playfair Display italic fused into "FA" in Space Grotesk, with a
gold diamond marking the seam (see the comment at the top of that file for
the full rationale). It's already a considered design; this skill is about
making it consistent everywhere it's used and giving it real staying power,
not redesigning it from scratch.

## Resolved gaps (keep these patterns when the wordmark changes)

1. **OG image is a real screenshot of the live components, not a fabricated
   graphic.** `public/og-image.jpg` (1200×630, referenced from
   `app/layout.tsx`'s `openGraph`/`twitter` metadata) was generated by
   temporarily adding a route (e.g. `app/og-preview/page.tsx`) that renders
   `Logo` plus the real hero copy at exact pixel size, screenshotting it
   with Playwright (`viewport: {width:1200, height:630}`,
   `deviceScaleFactor: 1` — a scale factor other than 1 will produce a
   file whose actual pixel dimensions don't match the declared
   `width`/`height` in metadata, so keep it at 1), then deleting the
   temporary route. Regenerate this way again if the wordmark, palette, or
   hero copy changes significantly — don't hand-author a new OG image in
   an external tool, it'll drift from the live brand.
2. **Favicon now has a full icon set, one shared source.**
   `public/favicon.svg` (circle + gold diamond) is rasterized via `sharp`
   into `favicon-16x16.png`, `favicon-32x32.png`, `apple-touch-icon.png`
   (180×180, flattened onto solid `#17140F` — iOS renders transparent PNGs
   unpredictably, so this one is NOT transparent, unlike the others), and
   `android-chrome-192x192.png`/`512x512.png`, wired up via
   `app/layout.tsx`'s `icons` field and `public/site.webmanifest`. If the
   mark changes, regenerate all of these from the same `favicon.svg` (see
   git history for the exact `sharp` resize/flatten calls) rather than
   editing each PNG by hand.
3. **Color values are duplicated by hand in three places.** The gold hex
   appears as `#B79355`/`#D4B87B` inline in `logo.tsx`'s SVG `fill`, again
   in `favicon.svg`, and as the `gold`/`gold.light` tokens in
   `tailwind.config.ts`. Inline SVG `fill` can't reference Tailwind classes,
   so exact duplication is somewhat unavoidable — but if `tailwind.config.ts`'s
   `gold` values ever change, grep for these two hex strings and update
   `logo.tsx` and `favicon.svg` (and regenerate the PNGs/OG image per above)
   in the same change, don't let them drift.
4. **The diamond has a subtle glint.** `tailwind.config.ts` defines a
   `diamond-glint` keyframe/animation (slow brightness pulse) applied to
   the diamond `<svg>` in `logo.tsx`, matching `.shimmer-text`/
   `.mirror-shine` elsewhere. It relies on the global
   `prefers-reduced-motion` CSS override in `globals.css` to collapse
   automatically — don't add a second, JS-driven reduced-motion check for
   it, the existing blanket rule already covers any CSS `animation`.

## Check every usage site when changing the mark

`Logo` is currently used in two places — `components/navbar.tsx` (`<Logo dark />`,
sized via the parent's `text-2xl`) and `components/footer.tsx` (`<Logo />`,
default/light variant). Both rely on the component's `em`-based sizing
(`text-[1.15em]` etc.) scaling with the parent's font size rather than a
fixed pixel size — preserve that when editing, and visually check both
usages (not just whichever one you're looking at) since the `dark` prop
changes the diamond's shade (`#D4B87B` vs `#B79355`) for contrast against
different backgrounds.

## Accessibility

The component already sets `aria-label="Sefa"` on the outer `<span>` with
the decorative diamond `aria-hidden="true"` — this is the correct pattern
(the `aria-label` gives screen readers the clean word "Sefa" instead of
"Se FA" fragments or the SVG). Preserve both attributes if refactoring;
don't let a screen reader end up hearing the two typeface halves announced
separately or the diamond described as an image.

## After a logo change

Run `visual-check` against both the navbar and footer usages, at a couple
of sizes, and in both light and dark contexts — and re-check the favicon
tab in a real browser (it's easy to update the wordmark and forget the
favicon still shows the old mark).
